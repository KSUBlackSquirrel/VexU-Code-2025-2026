Project Overview
Purpose
This project aims to recreate the **FRC-style Command-Based Framework** for VEX V5 robots using C++.  
The goal is to bring the modular, event-driven design of FRC’s WPILib Command System into the VEX ecosystem, allowing for cleaner organization, reusable logic, and more maintainable robot code.
Motivation
After working with FRC’s Java Command framework, I found its structure intuitive and scalable.  
When transitioning to VEX, I noticed there was no built-in framework that offered the same level of structure — most VEX programs are written as large, single files with logic spread across many custom functions.  
To address this, I began developing a custom VEX command architecture that mirrors FRC principles, including Commands, Subsystems, and a Scheduler that coordinates robot behavior.
Objectives
- Implement a lightweight Command Scheduler that manages lifecycle events (`initialize()`, `execute()`, `end()`).
- Develop a Subsystem Base Class that defines robot components as modular units.
- Define a consistent framework for writing drive commands, autonomous routines, and default subsystem behaviors.
- Support parallel and sequential command grouping for autonomous flexibility.
- Integrate seamlessly with PROS and external libraries like LemLib.
- Establish a foundation that can be extended by other teams for open-source use.
Design Philosophy
- Modularity: Commands and subsystems exist as independent components that can be tested and reused.  
- Reusability: Core logic (drive, intake, scheduler) can support multiple robots and projects.  
- Readability: Namespaced headers and consistent file structure make the system approachable for new developers.  
- Extensibility: Easy to add new subsystems and commands without rewriting existing code.
Expected Outcomes
- A functional C++ command framework for VEX V5 compatible with PROS.
- Clean abstraction of robot logic, similar to WPILib’s CommandScheduler.  
- Documentation and examples showing how teams can adopt the framework in their own projects.  
- Improved code maintainability, enabling faster development and easier collaboration.

Project Overview
===============
Purpose
-------
This project aims to recreate the **FRC-style Command-Based Framework** for VEX V5 robots using C++. The goal is to bring the modular, event-driven design of FRC’s WPILib Command System into the VEX ecosystem, allowing for cleaner organization, reusable logic, and more maintainable robot code.

Motivation
----------
After working with FRC’s Java Command framework, I found its structure intuitive and scalable. When transitioning to VEX, I noticed there was no built-in framework that offered the same level of structure — most VEX programs are written as large, single files with logic spread across many custom functions. To address this, I began developing a custom VEX command architecture that mirrors FRC principles (Commands, Subsystems, Scheduler) and adapts them to PROS and common VEX constraints.

Objectives
----------
- Implement a lightweight Command Scheduler that manages lifecycle events (`initialize()`, `execute()`, `isFinished()`, `end()`) and enforces command requirements (prevents conflicting use of subsystems).
    - Notes & behavior:
        - The Scheduler calls `initialize()` once when a command starts, calls `execute()` each scheduler cycle until `isFinished()` returns true, then calls `end(interrupted)`; it also runs subsystem `periodic()` and applies default commands.
        - Scheduling clones commands: `Scheduler::schedule(const CommandBase*)` clones the passed command (`cmd->clone()`) and stores the clone in its internal queue (`m_queue`). Callers should treat scheduled command pointers as prototypes; the running instance is the cloned object owned by the Scheduler.
        - Default commands are kept as raw pointers via `setDefaultCommand()`; the Scheduler clones the default pointer when it schedules it. Ensure the pointer passed as a default remains valid for program lifetime (commonly a static/global prototype).
- Develop `SubsystemBase` that represents hardware/logical units, auto-registers for periodic updates, and supports a single default command.
- Define a consistent framework for writing drive commands, autonomous routines, and default subsystem behaviors.
 - Support command composition: Sequential and Parallel command groups for autonomous flexibility.
     - `SequentialCommandGroup`: run children in order; next starts when previous finishes. (Children are marked composed so they cannot be scheduled standalone.)
     - `ParallelCommandGroup`: run children simultaneously; finish policy configurable (all finish, any finish, or race). (Children are marked composed so they cannot be scheduled standalone.)
- Provide command decorators like `andThen()` to chain commands easily (implemented as a convenience returning a sequential group).
- Integrate cleanly with PROS and optional libraries (LemLib for odometry/paths, LVGL for UI/auton selector).
- Document the framework and provide examples so other teams can adopt or extend it.

Design Philosophy
-----------------
- Modularity: commands are small and composable; subsystems own hardware and expose minimal APIs.
- Reusability: prefer small focused commands that can be combined for complex behavior.
- Readability: short, well-named files and a stable folder layout to help new team members and judges.
- Safety: default commands and a scheduler watchdog to prevent motors from being left uncontrolled.

Expected Outcomes
-----------------
- A functional C++ command framework for VEX V5 compatible with PROS.
- Clean abstraction of robot logic, similar in spirit to WPILib’s CommandScheduler.
- Documentation and examples showing how teams can adopt the framework.

Project Overview
Purpose
This project recreates the FRC-style Command-Based Framework for VEX V5 robots using C++.
 The goal is to bring the organized, event-driven design used in FRC’s WPILib system into the VEX ecosystem.
 By doing so, robot programs become easier to understand, reuse, and maintain.
 Instead of one large block of code, the robot’s behavior is divided into small, focused “commands” that work together under a central Scheduler.

Motivation
While programming in FRC, I learned the Command-Based model and found it clear, scalable, and ideal for teamwork.
 When I switched to VEX, I discovered there was no similar framework—most teams rely on one long file filled with custom logic that’s difficult to debug or extend.
 To fix that, I’m building a VEX-specific Command Framework that follows the same core ideas as FRC:
Commands perform short, specific robot actions.


Subsystems represent physical components like the drive or intake.


A Scheduler coordinates which commands run and prevents conflicts.


This lets the robot’s software act more like a well-managed team—each part knows its job and when to do it.

Objectives
Develop a Command Scheduler that manages command lifecycles (initialize(), execute(), isFinished(), end()), prevents subsystem conflicts, and calls each subsystem’s regular update function.


Example: the scheduler automatically starts and stops commands while keeping the drivetrain’s default behavior active when no other command is using it.


Build a Subsystem Base Class that represents a hardware unit and registers itself for periodic updates.


Define a consistent framework for writing drive commands, autonomous routines, and default subsystem behaviors—making robot code predictable and reusable.


Support command composition, allowing multiple actions to run one after another or at the same time.


Sequential groups run steps in order; parallel groups run tasks together until all (or one) finish.


Add simple “command decorators” such as andThen() to chain commands for readable, story-like autonomous code.


Ensure clean integration with PROS and optional libraries like LemLib (for motion control) and LVGL (for user interfaces).


Provide documentation and examples so other teams—whether technical or not—can adopt or extend the framework easily.



Design Philosophy
Modularity: Each robot function is small and independent.


Reusability: Commands can be combined to create new routines without rewriting old code.


Readability: Organized folders and short, descriptive files help new members and judges navigate the project.


Safety: A scheduler watchdog prevents motors from running unchecked and keeps control loops reliable.



Expected Outcomes
A fully functional Command Framework for VEX V5 in C++, built on PROS.


Cleaner, more logical organization of robot code that mirrors FRC’s proven structure.


Public documentation and code examples showing how other teams can benefit from this design.
